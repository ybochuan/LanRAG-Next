# FAM-04 文档族统一工作台

依据[文档族架构决策](../../design/ADR-Document-Family-2026-11-09.md)。单文件可保持未归族，观察链只在版本历史中解释。

1. 扩展读模型按同库业务族读取当前成员、移除历史、发布头、内外关系及已完成的治理动作。复用生命周期详情、血缘及关系现有事实。标明关系状态与方向，撤销后退出当前视图，历史证据留存。
2. 通过原生 JWT 知识库管理路径开放工作台所需的明确读动作。原生权限仍判定同库读取和写入，前端仅调用这条路径。复用现有成员、关系、日期和替代命令。
3. 增加以族为入口的工作台，支持未归族文档、族内外关系、成员状态、已发布版本、待办与审计。替代显式显示旧件失效效果。用跨库切换和只读账号验证读写边界。
4. 区分归族建议和关系建议。按库保存证据、权重、阈值与确认或忽略的结果。未确认不写成员或关系；涉及失效的候选进入已有替代审核。候选失败不影响文档操作。
5. 在隔离 Core/Host 与前端联合验证。正式验收前逐库准备 20–50 组人工标注，复核精确率 ≥ 0.70、召回率 ≥ 0.60。正式部署和真实库切换分别记录备份、映射审批及回切条件。

## 候选与校准

- 由管理员发起同库扫描，Host 在后台逐页查找，当前上传、检索和审批可继续。首批支持归族、相关、修订、解释和同族替代。标题词片相似、版本年份、显式提及、分块哈希/数量和本地标题语义均有各自证据。
- 若启用语义信号，Host 只将通过当前许可和观察版本核验的标题发送到本地 `/v1/embeddings`，在扩展内计算余弦，评分取标题词片与本地语义中的较高值。配置 `AGENTRAG_FAMILY_EMBEDDING_ORIGIN=http://127.0.0.1:8081` 与实际模型别名 `AGENTRAG_FAMILY_EMBEDDING_MODEL`。只接受当前 Host 网络空间可达的 HTTP 回环地址；模型服务应关闭请求正文日志。模型不可用时该次扫描可继续用标题等证据。
- 每条建议保存两端观察版本和评分配置修订号。忽略后同一候选不会因重复扫描而恢复。确认归族或关系时重新核对范围、两端版本和资格，业务写入与候选回执、审计同事务提交。普通建议可在当前页批量逐条确认，响应未知时保留未完成请求的原操作编号。确认替代建议仅创建待审批计划。
- 每库准备 20–50 对人工标注数据，包含应建议和不应建议的近似文档，覆盖该库实际年份格式、同名不同制度、补充、修订和非关联反例。按主题组分为训练集和留出集，文档或主题组不可跨集。只抽取已经提示的候选会高估召回率，须从待评估范围独立采样。
- 使用本地原生已核验标题、描述与版本证据中的分块哈希准备清单。顶层字段为 `knowledge_base_id`、`pairs`；每对填写 `group`、`partition`（`train` 或 `holdout`）、`expected`（`none`、`membership`、`related_to`、`amends`、`interprets`、`supersedes`）、`peer_membership`（`unassigned`、`same`、`other`），及 `peer`、`anchor` 对象的 `id`、`title`、可选 `description` 和 `chunk_hashes`。已确认发布件可填 `published_document_id`。
- 在 `extensions/` 执行 `go run ./cmd/family-calibrate <manifest.json>`。若正式扫描启用本地向量，校准须使用同一个回环模型配置。网格搜索只用训练集，留出集按类型判定正确性。训练和留出集均达到精确率 ≥ 0.70、召回率 ≥ 0.60 后，才在工作台应用推荐权重与阈值并重扫。保留各库清单版本、标签人、报告和配置修订号。真实语料报告仍待提供。

## 隔离验收记录

原生 `GET /api/v1/knowledge-bases/:id/lifecycle/business/:action` 开放 `family_list`、`family_members`、`family_workspace`、`family_replacements` 和 `family_suggestions`，沿用登录及知识库授权。治理写入仍走原有管理路径。

真实 Lite Core、worker Host、独立 SQLite、前端构建产物和 Chrome 联合回归退出 0。模型使用本地测试夹具，语义回归核对了请求范围与凭据隔离，真实语料指标另行验收。

| 验收范围 | 已验证的行为 |
|---|---|
| FAM-01／FAM-02 | 三份独立文档在同一业务族保留各自观察链。替代草案未改变检索许可；确认预约后暂扣新件，到期切换为新件可用、旧件 `superseded`。业务发布头锚定审批版本，关键边由新件指向旧件，重复审批返回原回执。 |
| FAM-03 | 只读盘点从历史发布及关键边得到候选，确认后可幂等回放。图与原生标签按库启用及回切，原用户标签保留，外键检查无违规。 |
| FAM-04 | 工作台显示外部关系，撤销后当前视图移除、历史和审计仍可查。实测五项读动作、管理员与只读成员登录、只读写入 403、匿名 401 及跨库拒绝。Chrome 显示语义证据和角色对应的操作入口。 |
| 候选行为 | 实际后台扫描分别生成归族与替代候选，展示依据和方向。未确认时成员与生命周期保持原状，忽略后重扫不再出现。扩展测试另验证普通建议确认的审计事务和替代建议的单独审批。 |

在仓库根目录的 Linux/WSL 环境使用隔离数据库，准备可用的 Lite Core 和 `frontend/dist`，确保测试网络中的 8090 空闲。令 `CORE_BINARY` 指向本次构建的 Lite Core。需要浏览器联合验收时，设置 `AGENTRAG_FAMILY_BROWSER_NODE`、`AGENTRAG_FAMILY_BROWSER_SCRIPT`（指向 `frontend/scripts/verify-family-workspace.mjs`）、`AGENTRAG_FAMILY_BROWSER_CHROMIUM`、`AGENTRAG_FAMILY_BROWSER_PLAYWRIGHT` 为可执行文件或模块的实际路径，浏览器须能访问测试 Core 的回环地址。设置 `AGENTRAG_E2E_TMPDIR` 和 `AGENTRAG_GOVERNANCE_REPORT` 可将数据库及报告放在临时目录。运行以下组合。

```bash
AGENTRAG_BUSINESS_E2E=1 AGENTRAG_LINEAGE_E2E=1 \
AGENTRAG_FAMILY_E2E=1 AGENTRAG_FAMILY_REPLACEMENT_E2E=1 AGENTRAG_FAMILY_CUTOVER_E2E=1 \
AGENTRAG_FAMILY_SUGGESTION_E2E=1 AGENTRAG_FAMILY_SEMANTIC_E2E=1 AGENTRAG_FAMILY_JWT_E2E=1 \
python3 extensions/scripts/governance_e2e.py
```

验收时核对 `[FAM-01]`、`[FAM-02]`、`[FAM-03]`、`[FAM-04-WORKSPACE]`、`[FAM-04-SUGGESTIONS]`、`[FAM-04-JWT]`、`[FAM-04-BROWSER]` 和 `[FAM-04-SEMANTIC]` 均为 PASS，且进程退出 0。浏览器夹具可在 `frontend/` 单独执行 `node scripts/verify-family-workspace.mjs`，沿用 `BROWSERSKILL_TEST_CHROMIUM` 和 `BROWSERSKILL_TEST_PLAYWRIGHT`，复验批量确认和切库交互。

## 正式部署和数据迁移

1. **按库校准。** 使用上述真实语料流程留存训练集、留出集和评分报告。每库准备 20–50 组人工标注，精确率 ≥ 0.70、召回率 ≥ 0.60 后再应用该库权重和阈值。
2. **核对发布组合。** 用待发布的 Core、Host 与前端复跑隔离联合回归。检查目标配置下的角色授权、登录及知识库范围。按 [发布与回滚流程](../../operations/REL-04-发布与回滚.md) 对原生库、扩展库做一致备份，演练恢复，并在副本升级后核对 `integrity_check`、`foreign_key_check`、既有观察链和历史审计计数。
3. **逐库回填与试切。** 使用 Host 的 `family_backfill_plans` 只读盘点，审批旧链到业务族的映射与预览指纹，再以 `family_backfill_apply` 显式确认。对缺失文档、歧义链、拆分记录单列复核。先选一库试切，核对发布头、观察链、图和原生标签，确认 Outbox 已处理完且用户标签保留，再逐库扩展。
4. **投影自动执行。** 业务族成员与发布头变更后自动向 Outbox 入队 `family_tag`，由单写者按当前事实重算 `gov:family:` 标签；不再提供逐库关闭开关。业务族登记、发布头、生命周期和审计属于治理事实，与投影相互独立。
