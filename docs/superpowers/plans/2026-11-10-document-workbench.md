# 文档工作台实施计划

用户已确认文档台账、单文档详情和回答反馈设计。保留现有治理事务、知识库权限与历史记录。旧菜单入口集中到「文档工作台」，旧地址继续定位到对应功能。

1. **入口与台账。** 修改前端路由、菜单和 `LifecycleView.vue`。沿用按库搜索、七类状态、待复核和库级规则。列表与详情返回当前业务版本族，未归族文档可打开。验证旧地址、切库、只读权限及搜索。
2. **单文档详情。** 复用日期、补充、版本族、关联、修订及血缘组件。通过现有原生授权入口传入文档身份，在扩展模块按文档筛选记录。图中可从关联节点打开对应文档。观察链字段退出新视图，旧接口保留过渡兼容。验证同库未归族文档、替代历史、关联方向、分页和跨库拒绝。
3. **回答反馈。** 回答块接收评价、意见和建议修订。审核工作台区分问答提交与既有手工记录。审核员只看到明确提交的问答摘录及已绑定的引用，审核后确认的指导沿用冷静期和激活门槛。验证待审和驳回内容不进入后续问答，激活后仅在现有许可范围内注入。

使用隔离数据库和前端构建产物验收。原生端已有的会话来源和写权限继续生效。扩大反馈提交角色或读取私有会话正文需另行确认原生接口范围。

隔离接口回归使用 `AGENTRAG_QA_FEEDBACK_E2E=1`、`AGENTRAG_GUIDANCE_E2E=1` 和 FAM 联合选项运行 `extensions/scripts/governance_e2e.py`。核对 `[DOCUMENT-WORKBENCH]` 和 `[DOCUMENT-FEEDBACK]`，分别覆盖确认归族、文档关系与审计、外库拒绝，以及反馈摘录、冷静期、核验引用和后续生成范围。

联合回归使用真实 Core、Host、前端构建和 Chrome，退出 0。浏览器验证旧入口跳转、侧栏菜单收敛、台账搜索、日期表单、单文档关系图和审计、审核员查看反馈与核验引用、只读角色限制。模型使用本地夹具，冷静期通过推进隔离记录的到期时间验证。

正式发布需按发布与回滚流程备份扩展库并在副本上升至 schema 28。观察链的内部身份和既有事实继续保留。退役旧 API 的兼容字段前，盘点现有调用方并验证正式环境的版本历史和审计。

- 从主件的「关联关系」可打开补充通知，在该通知详情维护依赖。撤销后当前关系列表移除声明，治理记录保留该操作。建议确认和忽略显示在两端文档的治理记录。
