# REL-06 制度废止实施计划

> **For agentic workers:** Use the executing-plans workflow. Check off each step against its actual test result.

**目标**。审批人确认同库废止通知和旧制度，按批准时点使旧制度退出常规读取，保留废止依据、版本和审计。

**取舍**。复用现有文档关联页、JWT 管理转发和生命周期归档状态。单独在扩展库保存废止时点与批准记录，投影 `repeals`，以免改写既有关系枚举或让仅供导航的关系驱动状态。管理者可先提交后批准。撤回适用于未生效记录，已生效后不得从该入口恢复旧件。

**依据**。[文档关联总体改造](../../design/文档关联总体改造.md#待定能力清单)。

## 规则

- `repeal_create` 传入通知、旧制度及显式生效时间。两端同库、不同文档，且当前版本有效。提交、批准和执行均核对版本。批准已到时的记录立即尝试生效，未来记录由 worker 扫描。
- 同一旧件只能有一条已批准的待执行记录。版本错配、已删除或已停用时进入待复核。暂时无法读取源证据时保留计划并重试。
- 到时而尚未提交的计划暂时阻断该旧件的常规检索、附件和已封存来源读取。执行成功后，以同一事务提交的生命周期事件、当前状态、Outbox、废止凭证和审计为准。保留按权限查阅历史的能力。
- 原生接口、既有生命周期枚举及关键血缘枚举沿用当前实现。只用隔离库验收候选。
