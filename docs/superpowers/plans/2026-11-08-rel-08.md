# REL-08 转换件溯源实施计划

将正式解析产物关联到经过核验的原件版本。首批覆盖持久 MinerU V1 作业的 `middle.json`。阅读版 Markdown 与其他转换格式使用独立的产物类型，等对应字节能由同一正式作业证明后接入。

## 冲突点

- `ext_parser_artifacts` 现有记录把结果绑定到解析身份、作业和 MinerU 文件 ID。`ext_parser_documents.snapshot.Hashes` 保存代理验证的原件 SHA-256。原生版本快照中的 `file_hash` 则是原生文件哈希字段的摘要。直接比较两种摘要，或以 `doc_id` 把已存在的产物挂到最新版本，会把旧转换件绑定到错误的原件。
- 原生原件下载需要登录、Contributor 及文档所在库写权限。现有关联列表只要求库读权限。转换件可能含整篇正文，需要沿用原件下载的权限边界。

## 实施顺序

- [ ] 在 `extensions/parser/` 从持久回执读取确定的原件 SHA-256、作业和产物指纹。用原生受限下载接口获取有大小上限的原件，并以 SHA-256 与回执核对。下载前后捕获原生快照，版本变化时拒绝绑定。旧数据按同一证据核验，缺回执或摘要时留作未绑定。
- [ ] 在 `extensions/store/migrations/`、`extensions/lineage/` 加入只增的绑定事实。登记产物与准确的已观察版本，以 `rendition_of` 从产物指向原件，保留旧记录，重试复用同一凭证。当前图和读取只引用已绑定记录，原件版本变化、不可读或产物校验失败时拒绝。
- [ ] 在 `extensions/management/` 先提供受限只读契约和测试。原生下载入口如需接线，先核对实际路由与下载权限，再按受控区规则提供薄补丁清单。文件响应使用原始字节及受限文件名。
- [ ] 隔离验证真实解析闭环、不同原件共用文档 ID、相同字节不同文档、跨库和权限负例、废止与到期、重复绑定、重启及丢响应后复用。候选库须通过完整性和外键检查。
