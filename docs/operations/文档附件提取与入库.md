# 文档附件提取与独立入库

阶段一支持真正的内嵌文件及DOCX正文末尾独立标题附录。每个提取结果通过原生文件上传API成为同库独立文档，在原生文档列表可见；不改主文档原件，也不要求目录中有附件条目。

## 支持范围

| 来源 | 处理 |
|---|---|
| PDF | `pdfcpu.ExtractAttachmentsRaw`读取实际内嵌白名单文件 |
| DOCX/XLSX/PPTX | 读取`word/embeddings/`、`xl/embeddings/`、`ppt/embeddings/`；OLE `.bin`不解包 |
| DOCX正文附录 | 独立段落“附件1”“附件2-1”“附件一”等作为分界；普通“详见附件1”引用不拆。保留该段落起至下一标题前的段落、表格及末尾section；样式、资源保留原包。输出`annex-01.docx`等 |

导入只提取一层。子文档Metadata `is_attachment`为`"true"`时跳过再次提取，避免正文仍含附件标题导致递归。白名单为`.pdf/.docx/.xlsx/.pptx`，扩展名和基本容器类型共同检查。单件必须**严格小于20MiB**，源最大50MiB，单批最多32件、合计64MiB；超批次上限返回错误，不静默截断。

## 启用

需要重新编译本批原生薄补丁和Host；当前运行的旧二进制不会自动获得入口。在WSL仓库根执行候选构建（不会覆盖原件）：

```bash
CGO_ENABLED=1 go build -mod=readonly -tags=lite,sqlite_fts5 \
  -ldflags='-X github.com/Tencent/WeKnora/internal/handler.Edition=lite' \
  -o tmp/WeKnora-lite-attachments-check ./cmd/server
(cd extensions && CGO_ENABLED=0 go build -mod=readonly -o ../tmp/extension-host-attachments ./cmd/extension-host)
```

Office正文继续使用原来配置的解析引擎。若使用本地anydoc，需保留既有`anydoc`构建标签和静态库（可用时把标签写为`lite,sqlite_fts5,anydoc`）；若使用DocReader，需要保持其服务可用和正确的`DOCREADER_ADDR`/`DOCREADER_TRANSPORT`。本功能不把Office正文交给PDF-only MinerU，也不代替安装Office解析引擎。

沿用[启动与运维指南](AgentRAG-启动与运维指南.md)的worker配置及凭据，不新增附件专用密钥：

- Core：`AGENTRAG_PARSER_PROXY_ADDR=http://127.0.0.1:8090`，`AGENTRAG_PARSER_PROXY_KEY`与Host一致。
- Host：`AGENTRAG_MODE=worker`、独立`AGENTRAG_EXT_DB`、原生API地址/机器凭据、`AGENTRAG_TENANT_ID`及`AGENTRAG_KB_IDS`；机器凭据需同库`retrieve`和`ingest`能力。
- Host现有Parser配置：`AGENTRAG_PARSER_UPSTREAM_URL`、`AGENTRAG_PARSER_ARTIFACT_ROOT`、`AGENTRAG_PARSER_SCOPES`、`AGENTRAG_PARSER_PROXY_KEY`。一键脚本将`MINERU_ENDPOINT`映射为前者，身份与共享密钥沿用已有配置。
- Host仍仅监听`127.0.0.1:8090`；先确认`/health` ready，再启动Core。Host未配置Importer、凭证/身份错误或导入失败时不会默默跳过附件。

配置后从原生页面或`POST /api/v1/knowledge-bases/{kb}/knowledge/file`正常上传主文档即可。PDF在源字节核验后、预检前执行提取；Office在原生reader前调用`POST /parser/native/v1/attachments`。原生分块/索引照常继续。附件和主文档均可通过原生列表/下载API验收。

原生Metadata类型是`map[string]string`，因此强制写入：

```json
{"is_attachment":"true","parent_document_id":"原生主文档ID","attachment_sha256":"提取文件的SHA256"}
```

## 去重与失败

同Host串行导入，重试先查询原生列表；只有tenant、KB、父文档及附件SHA256全部匹配才复用原ID。上传应答未知时不立即重复POST。原生按相同文件字节去重，遇到另一个父文档/普通文档的409会拒绝，而不覆盖其Metadata。已经成功的子文档保留，整批不承诺原子事务或跨Host exactly-once；修复问题后由原生重试或重新调用提取即可对账已知结果。

阶段一的`parent_document_id`只是关系标记。阶段二／三现已在检索许可及原生文档下载时查询该父文档生命周期：附件自身和同库父文档都必须active；父stale、archived、其他非active或缺失时排除。**不写`ext_lineage_edge`、不自动改变子状态，也不等于完整来源证明。** 正文拆分不猜测普通引用或缺少独立标题的附录边界；不保证自动保留原章节页码/交叉引用语义。

## 检索关联与聊天下载（阶段二／三）

重新构建并启动本批Core/Host/前端后，命中主文档会在回答下方显示相关附件卡片，直接命中附件则显示该附件。服务端Metadata字段为`metadata.related_attachments`（JSON数组字符串），每项含`knowledge_id`、`knowledge_base_id`、`parent_document_id`、`file_name`、`download_url`。同一附件多个chunk/RAG与Agent引用只显示一次。

链接沿用原生`/api/v1/knowledge/{id}/download`文档接口；`/files`是另一个存储代理。卡片和已登记的Markdown链接通过已有登录请求函数下载Blob，凭据不放进URL。保留原生下载的编辑权限要求；只有读取权限的分享用户不会因出现卡片而新增下载权限。

Host继续使用`AGENTRAG_MODE=worker`、原生机器凭据的同库retrieve能力，及现有Parser配置；额外确保**Core和Host的`AGENTRAG_MANAGEMENT_KEY`相同且至少32字节**。一键脚本已有该配置，分开启动需自行保持一致。`after_retrieve`用该服务端凭据，不向浏览器下发；凭据/增强不可用时回答仍可继续，但附件链接省略。既有before_retrieve和附件下载继续失败关闭。

父状态改变后，新问答不再返回失效附件链接。旧消息保留原卡片，点击下载时重新查询当前许可并返回403，前端提示所属制度可能过期或权限变化。Host断开也返回403。本批只覆盖该原生文档下载入口；不声明原生`/files`存储路径、已签发资源、已经下载到本地的文件或已输出答案内容被撤销。

本批候选构建示例（WSL仓库根；保留生产Office引擎所需构建标签）：

```bash
CGO_ENABLED=1 go build -mod=readonly -tags=lite,sqlite_fts5 \
  -ldflags='-X github.com/Tencent/WeKnora/internal/handler.Edition=lite' \
  -o tmp/WeKnora-lite-attachment-downloads ./cmd/server
(cd extensions && CGO_ENABLED=0 go build -mod=readonly -o ../tmp/extension-host-attachments ./cmd/extension-host)
(cd frontend && npm run type-check && npm run build)
```

生产静态资源仍需按原启动指引部署到Core配置的`WEKNORA_WEB_DIR`；单独`npm run build`不自动替换当前运行的服务。开发模式可使用原前端开发服务。验收命令加`--governance`会自动验证真实上传、RAG/Agent Metadata、父日期扫描及断Host下载拦截：

```bash
unshare -Urn -- sh -c 'ip link set lo up && exec "$@"' sh \
  env CORE_BINARY="$PWD/tmp/WeKnora-lite-attachment-downloads" \
  python3 "$PWD/extensions/scripts/attachment_e2e.py" --governance
```

该模式用合成DOCX及本地模型/Office夹具；用户真实六附录样本的拆分与表格保留仍见阶段一证据。阶段二／三完整记录与真实组件截图见[下载联动验收](../evidence/attachment-downloads-2026-11-03.md)。

## 自动验收

WSL空闲8090时执行：

```bash
CORE_BINARY="$PWD/tmp/WeKnora-lite-attachments-check" \
  python3 extensions/scripts/attachment_e2e.py
# 自有样本，源文件只读；相应指定期望附录/表格数量
CORE_BINARY="$PWD/tmp/WeKnora-lite-attachments-check" \
  python3 extensions/scripts/attachment_e2e.py --sample "$SAMPLE" \
    --expected-annexes 6 --expected-tables 4
```

生产8090已占用时，在仅本次测试的新网络命名空间中先启用回环再执行，避免停生产进程：

```bash
unshare -Urn -- sh -c 'ip link set lo up && exec "$@"' sh \
  env CORE_BINARY="$PWD/tmp/WeKnora-lite-attachments-check" \
  python3 "$PWD/extensions/scripts/attachment_e2e.py" --sample "$SAMPLE"
```

脚本创建新账号/库、私有Core/Host、独立SQLite与测试服务；日志只打印计数/验证结果，原始诊断留在Git忽略的`tmp/attachment-e2e-*/`。**Office转换和模型是本地测试夹具**，真实验证的是原生上传、身份、自动提取、API入库、存储、列表、重复对账及原生分块，不代表生产Office引擎/MinerU/云模型联合验收。详见[本轮证据](../evidence/attachments-2026-11-03.md)。
