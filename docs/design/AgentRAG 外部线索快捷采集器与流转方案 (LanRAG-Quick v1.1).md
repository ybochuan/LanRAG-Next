# AgentRAG 外部线索快捷采集器与流转方案 (LanRAG-Quick v1.1)

## 1. 定位与目标

构建一个常驻桌面的极简采集工具。通过快捷键或右键菜单抓取外部网页、本地文件或文本片段，作为“外部线索 (Clue)”进入治理流水线。
**核心工程原则**：

- **原生优先，本地兜底**：网页抓取优先调原生 URL 导入能力，失败时降级本地算法提取。
- **快照为尊**：审批入库时**强制使用本地快照**，绝不让原生重新抓取 URL，防止内容篡改或失效。
- **能力复用**：完全复用原生 `KnowledgeTag` 体系和 Metadata 元数据，不重写存储。

## 2. 多通道交互采集设计

### 2.1 全局快捷键（支持自定义防冲突）

- 默认 `Ctrl+Shift+S`。可在托盘设置中自定义，使用 `golang.design/x/hotkey` 动态热更新，若冲突则标红提示。
- **触发逻辑**：读取剪贴板。纯文本弹窗录入；若为 URL 则触发后台抓取流程。

### 2.2 浏览器与系统右键菜单

- **浏览器扩展**：支持网页选中文字存入，或链接右键抓取。
- **Windows 系统右键**：注入注册表（仅 `HKEY_CURRENT_USER`），支持文件（PDF/DOCX）右键 `存入 AgentRAG`。

### 2.3 系统托盘

常驻右下角，提供偏好设置、手动输入、退出功能。提交成功弹出系统原生通知。

## 3. 采集引擎：原生优先，本地兜底

在 Extension Host (`extensions/clipper/`) 中执行：

1. **快速通道（原生）**：收到 URL 后，优先尝试调用 WeKnora 原生的 `POST /knowledge/url` 接口进行抓取，依赖原生配置的 `SSRF_WHITELIST`（需在配置文档中提醒用户配置常用域名）。
2. **兜底通道（本地）**：若原生抓取失败（如反爬），降级使用 `go-readability` 提取正文并转 Markdown。
3. **物理快照（强制）**：无论通过哪种通道，最终提取的正文**必须**保存到 `data/clips/{timestamp}_{title}.md`。

## 4. 治理审批工作台（增强版）

抓取的内容生成 `ext_feedback_events`，触发反思 Agent 生成与内部库的 Diff。在 Web 端审批弹窗中展示：

```text
┌──────────────────────────────────────────────────────────┐
│ 📥 沉淀为外部知识文档                                    │
├──────────────────────────────────────────────────────────┤
│ 1. 目标与标签                                            │
│ 目标知识库: [ 财务制度库 ▼ ]                             │
│ 文档名称:   [ 2026年最新差旅报销补充规定.md          ] │
│ 来源标签:   [x] gov:source:web  [x] gov:doctype:external │
│ 大小提示:   ✅ 120KB (未超出目标知识库 50MB 限制)        │
│                                                          │
│ 2. 关联内部知识 (血缘)                                   │
│ 💡 Agent 发现该内容与以下制度高度相关：                  │
│ [✓] 《2024差旅报销管理办法》                             │
│     关联类型: [ 补充说明 (supplements) ▼ ]               │
│                                                          │
│ 3. 内容预览 (基于本地快照)                               │
│ # 2026年最新差旅报销...                                  │
│                                                          │
│              [ 取消 ]  [ 确认入库 ]                      │
└──────────────────────────────────────────────────────────┘
```

*注：前端在此弹窗中需增加文件大小前置校验，防止入库报错。*

## 5. 入库执行与状态回写 (核心流转)

点击确认入库后，Extension Host 执行以下原子性流转（**绝不用 URL 重新抓取**）：

1. **读取本地快照**：读取 `data/clips/` 中的 Markdown 内容。
2. **调用原生文本录入 API**：调用 WeKnora 原生文件/Markdown 创建接口。
3. **透传原生 Metadata**：在入库参数中附带：
   
   ```json
   "metadata": {
     "source_url": "https://...",
     "captured_at": "2026-10-30...",
     "source_type": "web"
   }
   ```
   
   确保原生详情页也能看到来源。
4. **标签投影**：调用 `TagProjectionWriter` 打上 `gov:source:*`（**只作用于新建文档**，严守红线）。
5. **写入血缘边**：写入 `derived_from`（溯源原 URL）和 `supplements` / `amends`（关联内部制度）。
6. **状态回写（防止黑洞）**：在 `ext_feedback_staging` 记录 `ingest_status = processing`。启动后台轻量 Worker，每隔 10 秒轮询一次原生文档的 `parse_status`。如果失败，标红提示；成功则置为 `success`。

## 6. 安全与工程红线

1. **唯一事实来源**：入库的 Markdown 必须是审批时预览的那份本地快照。网页如果后续被篡改，不影响知识库。
2. **标签作用域限制**：Quick-Clipper 的标签注入**仅用于新建文档**。禁止对已有文档调用 `PUT` 覆盖标签。
3. **单机边界**：Quick-Clipper 仅限本机（`127.0.0.1`）使用，依赖 Lite 本机 API，不承担局域网多设备同步职责。
4. **SSRF 安全**：如果使用了原生 URL 抓取，必须在 README 中强调原生 `SSRF_WHITELIST` 的配置维护。

## 7. 工程落位建议

- **桌面插件/托盘**：`cmd/desktop-quick/`
- **浏览器扩展**：`extensions/ui/browser-extension/`
- **抓取与解析逻辑**：`extensions/clipper/`
- **Web 端审批台**：与治理工作台融合，增加来源标签、文件大小校验、Diff 视图及血缘选择功能。
