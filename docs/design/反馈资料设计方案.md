# 反馈资料设计方案

**评审稿 · 2026-11-20**

在文档工作台统一查看反馈和已审核勘误。每个原文版本维护一份由系统生成的 `XXX反馈文档.md`，按日期汇总勘误。问答按条检索、按版本核验。已经生效的勘误随原文版本持续有效，同一会话可以反复使用。需要修正文档正文时，通过现有修订发布流程发布正式新版。

## 1. 目标与现状

- **反馈有去处。** 用户对答案提交反馈，审核员能定位原文、核对摘录并定稿。文档读者可从原文版本打开已公开的勘误。
- **修正能持续。** 只要原文当前可用、用户获授权且问题符合适用条件，第三次、第五次追问仍能使用同一条勘误。
- **问答有依据。** 用户自然发问时，系统确保知识库问答先完成授权检索。回答引用原文与实际使用的勘误。
- **失效可验证。** 撤回、到期、停用、删除、换版或权限收回后，下一轮按当时状态核验，搜索索引中的旧条目也必须通过同一校验。

当前审核已独立保存原始反馈、审核定稿、适用条件和来源锚点。旧指导机制对同一会话内的同一条指导限制为两次，并设有会话总预算。隔离 Qwen 回归中，前两次用了指导，第三次受次数限制。智能推理在自然问法下也出现过跳过搜索的情况。这两处分别需要改证据使用规则和检索触发规则。 [反馈数据结构](../../extensions/store/migrations/039_answer_feedback.sql#L2) · [现有指导预算](../../extensions/guidance/inject.go#L132) · [联合验收记录](../../tmp/feedback-optimization-governance.log) · [自然问法对照记录](../../tmp/feedback-optimization-final-natural.log)

## 3. 保存位置和文档结构

**由扩展服务统一保存，按原文权限归属。** 普通独立知识库方案要另外实现系统库防删、跨库继承权限、每个读入口的过滤和换版同步。扩展托管可以复用既有审核数据和同库锚点，工作台负责集中展示。原生知识库的正常删除会使相关勘误退出在线检索。 [知识库删除入口](../../internal/handler/knowledgebase.go#L1373) · [扩展持久存储配置](../../extensions/host/config.go#L100)

| 对象 | 保存规则 |
| --- | --- |
| 审核和发布记录 | 扩展数据库为业务事实来源。保留现有反馈 ID、审核修订、审批、撤回及替代历史。持久勘误绑定租户、原文库、文档、版本、原文章节或核验分块及指纹。所需最小核验信息随审核发布记录保存。 |
| Markdown | 受管目录按租户 ID、知识库 ID、文档 ID、版本 ID 分层，每个版本只有一份逻辑文件。落盘用稳定文件名 `feedback.md`，展示及下载名为 `XXX反馈文档.md`。原文改名更新展示名。受管文件路径仅对扩展进程可见。预览和下载重新核验原文权限，并按请求权限输出相应内容。 |
| 检索索引 | 按单条勘误索引，带完整原文归属、条目 ID 和审核修订。搜索入口返回已核验的条目及原文引用。每次消费重新核验，旧索引仅作为候选。 |

每条 Markdown 记录包括审核日期、反馈编号、原文位置、适用条件、修正口径和生效时间。审核日期按新到旧排列，同日以稳定 ID 保持顺序。效力由生效状态和显式替代关系决定。Markdown 只汇总可发布的审核定稿，原始问题、聊天摘录、提交人资料及内部审核备注继续在审核记录中按权限查看。

例如，《报销制度》某版第四条写「提交期限为 5 个自然日」。生效条目补充「适用松桥项目，提交期限为 5 个工作日」。询问松桥项目时，答复按已审核口径给出「5 个工作日」并同时引用第四条和勘误。问到其他项目时，按相应的原文与实际适用的勘误作答。

## 4. 审核、生效和正式修订

1. **提交并核验。** 复用问答反馈入口。审核员确认原文、版本、章节或分块位置和适用条件。来源不明确的反馈保留在审核队列，由审核员补齐证据。点赞与意见可留在反馈记录。
2. **审批并激活。** 沿用风险等级、冷静期和所需复核。冷静期结束、来源仍满足条件后激活。在同一扩展事务提交审核状态、审计和持久更新任务。勘误激活后随原文版本持续有效，记录状态与检索资格独立于会话和旧问答证据的滚动留存。
3. **生成文件并刷新索引。** 按来源版本重算 Markdown，按条目和修订幂等更新索引。写文件采用原子替换，更新任务失败可重试或全量重建。旧任务重试时读取最新修订，避免覆盖新状态。索引延迟期间，命中原文的问答仍能从已提交的记录读取相关有效勘误。
4. **撤回和替代。** 冲突口径由审核员明确受影响条款和替代关系。可区分适用范围的条目可以同时生效。重叠冲突尚未解决时，不发布新的冲突条目。撤回、过期、停用、删除、换版和权限收回均在在线读取时检查，随后更新索引。历史归档遵循现有审计与删除保留规则。
5. **发布新版。** 可从勘误发起正式修订提案，引用勘误 ID 和来源版本。新版索引完成并通过现有发布事务后，问答转引新正文，旧版反馈文档归档。新版仍有适用勘误时走重新核验和发布，避免把旧版结论自动带入。 [既有事务更新队列](../../extensions/outbox/store.go#L70) · [证据保留机制](../../extensions/retention/service.go#L47) · [现有修订发布流程](../../extensions/business/revision.go#L210)

## 5. 检索与问答

### 5.1 双向检索

- **先命中原文。** 通过现有授权检索取到原文分块，以本轮消费的章节或分块锁定当前版本，从扩展查找与问题及适用条件匹配的有效勘误。
- **先命中勘误。** 「哪项规定是 5 个工作日」可通过审核定稿命中，即使旧正文只写「自然日」。按当前调用者授权的知识库和文档范围搜索。系统再通过原文读取门卫获取所绑定的原始分块，并对照当前版本、正文指纹、可用性和生效状态。两者都进入本轮证据后才可使用勘误。
- **合并并引用。** 按原文位置和勘误 ID 合并重复命中。引用显示原文版本及「已审核勘误」条目。勘误适用且与原文表述冲突时，采用已生效的审核口径，并说明修正了哪一条。适用条件不明时询问条件或分别说明不同情形。审核定稿以证据正文传入，模型行为指令由系统统一提供。 [现有检索授权入口](../../internal/application/service/chat_pipeline/search_parallel.go#L104) · [现有来源核验](../../extensions/guidance/inject.go#L19)

### 5.2 同一会话连续追问

把勘误作为**本轮可重新取得的来源证据**。每轮都执行来源和勘误核验，按本轮条数、长度和模型上下文预算裁剪。保留同一请求的幂等去重，同一已生效勘误可在同一会话的不同轮次反复使用。

对「那从哪天算？」一类省略问法，沿用默认历史与查询改写，从上一轮用户问题和可核验的来源引用提取检索线索。重新授权并读取当前版本。历史回答中的修正口径和历史工具正文只可作为需要复核的上下文，当前已失效的证据不得进入下一轮知识库答案。换话题按新问题检索。对于无法完整归因的历史、附件或其他不透明输入，仍按现有来源规则处理。 [当前历史来源核验](../../internal/application/service/chat_pipeline/governance.go#L71)

### 5.3 智能推理自然问法

对已选择知识库或文档、且任务明确依赖库内证据的请求，系统在生成事实答案前安排一次现有的授权检索。跟进已引用条款的省略问法也进入该流程。收到证据后，Agent 可自主决定补查、读取相邻内容或结束。问候等无需查库的问题直接处理。明确查库但没有可用依据时，答复说明检索结果，避免从模型记忆补写制度期限。

验收的真实供应商请求不设置 `tool_choice`，用户也无需点名搜索工具。最少一次检索由应用流程保证，模型仍可以自主选择后续工具。快速问答与 Agent 复用同一勘误解析规则和引用语义。 [现有 Agent 检索提示](../../config/prompt_templates/agent_system_prompt.yaml#L43) · [当前 Agent 模型调用接点](../../internal/agent/think.go#L66)

## 6. 实施接口、迁移与运行保障

- **扩展模块管理业务。** 对原生问答提供一处受控接点，输入当前授权范围、问题和已核验来源引用，输出本轮可用勘误及来源标识。对工作台提供授权列表、详情和 Markdown 下载。只有具备治理权限的接口能审批、撤回或替代。原生适配保持薄层，沿用现有本机桥接和授权范围，检索与 Agent 算法复用原有实现。
- **既有数据迁移。** 带可靠原文锚点的已生效事实类勘误，逐条复核版本和指纹后生成文档与索引。同一勘误完成切换后由本轮证据通道提供，避免一次请求中重复出现。来源证据不足的记录保留供审核补证。普通指导与事实勘误使用各自规则。
- **兼容与故障处理。** 实施时按库灰度。回退时暂停新索引结果和新接线，审核状态、撤回状态和审计历史仍由原有治理数据提供。已失效条目不得借由回退重新出现。授权服务不可用时遵循现有检索拒绝规则。只有勘误索引不可用时，可先从已核验原文查生效记录。若勘误事实也不可读，则保留已核验原文的作答能力，并在需要时提示勘误状态暂未核验。
- **诊断和留存。** 记录匹配、发送、撤回、版本不符、权限不符和索引延迟等结果，关联条目、修订、来源版本与请求。正文和私有问答摘录留在各自受控记录里。「已发送」按实际请求确认，模型是否正确采用通过答案和引用回归衡量。

**实施前评审项。** 冻结方案 §10.2 规定旧指导的会话上限。本方案建议为已审核的事实勘误新增版本证据规则，并批准必要的原生薄接点及知识库问答先取证机制。两项均在实施前确认。具体持久目录、索引实现和每轮证据上限由实现阶段结合部署路径、延迟和模型上下文确定。 [冻结指导规则](<AgentRAG 技术方案 v1.0 — Frozen Architecture.md#L476>) · [核心改动约束](../../AGENTS.md#L13)

## 7. 验收清单

| 场景 | 通过条件 |
| --- | --- |
| 统一入口与 Markdown | 同一原文版本激活三条勘误，列表仍显示一个文档，内容按日期排序。原文同名、异库或换版产生独立归属。工作台、原文版本和引用链接能打开正确条目。 |
| 权限 | 普通读者仅看授权原文的有效定稿。跨租户、同租户越库、失权后访问旧链接、直接搜索、统计与导出均无越权结果。未归属及私有审核材料仅出现在授权审核入口。 |
| 双向检索 | 仅搜原文措辞与仅搜审核定稿，都能取得正确的原文和同一条勘误。无关话题、条件不符或来源不可验证时不采用该勘误。 |
| 连续追问 | 默认历史和查询改写开启，同一会话自然问法至少五轮，第三及第五轮仍使用适用勘误。包含省略追问和改问其他条款。中途撤回或停用后，下一轮没有旧勘误进入模型请求或答案引用。 |
| 智能推理 | 自然提问，无工具名、无强制 `tool_choice`。能观察到应用发起的授权检索、实际消费的原文与勘误、答案和双引用。无结果时说明未取得依据。复跑真实模型并记录模型版本、输入输出和偏差。 |
| 生命周期与正式修订 | 冷静期内未进入问答。有效期、撤回、删除、换版和权限变化立即影响下一轮。正式新版发布后引用新版正文，历史勘误可按权限追溯。 |
| 故障与恢复 | 并发审批、重复投递、写文件中断、旧任务晚到、索引延迟和恢复后，数据不丢失、不重复、旧勘误不回流。扩展重启和旧问答证据滚动清理后，当前版本的有效勘误仍可检索。 |

交付顺序建议为「托管文档与工作台」→「双向检索、五轮追问与自然问法」→「旧数据迁移与灰度」。界面、访问权限、实际模型请求与答案均通过后，再开放给生产用户。
