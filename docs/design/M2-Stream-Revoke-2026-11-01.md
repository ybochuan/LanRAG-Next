## 设计选择（待确认）

- 保持当前入口快照：没有新PATCH或网络开销；C-25限制保留，不能承诺生成中撤销。
- 推荐在来源完整后采用**可取消的来源许可**：扩展负责当前源集许可，原生只负责定时复核和取消既有context。before_generate的guidance失败放行仍独立保留。

来源许可规则拟定如下：

1. 许可绑定tenant、原生授权范围、服务端生成run/attempt ID、完整源集、内容/源版本及短有效期。客户端/模型不能签发complete或空源证明。
2. 有任意未知来源时不发许可；跨库按显式授权。没有受治理来源必须有可信协调层证明，不能把缺字段/空数组当作纯聊天并回退放行。
3. 扩展在一致读快照中核验全部源。原生使用既有固定回环和500ms请求上限，不缓存跨请求allow。能否直接复用before_retrieve协议，须在完整来源DTO确定后验证，不能假设当前scope已足够。
4. 检测到任一源非active/版本变化、Host不可用或许可过期，取消该次模型上下文，并标记为policy_revoked。后续重试、下一轮、自动fallback和异步通知不得重放受影响内容。
5. 原生只在明确批准的薄点判定cause、丢弃该次缓冲、停止新输出。既有用户停止、正常完成的flush语义保持。SSE层已经排队的内容需要单独验证，不能只断上游HTTP就承诺下游零输出。
6. 停止的回答沿用已有中断语义；不得伪装完整成功，不删除已有消息、源文件或外部模型记录。来源许可/撤销审计留在扩展事实层，source权限不由UI字段决定。

## 冲突与尚待决策

| 冲突 | 处理建议 |
|---|---|
| guidance的before_generate失败放行与治理来源许可失败拒绝不是同一语义 | 分离两个判断；不要把Frozen before_generate直接改为fail-closed。新的来源许可接线及Host不可用时取消必须获明确批准。 |
| 原生普通取消会flush解码缓冲；SSE/事件队列可持有已生成文本 | 需要专门的策略撤销cause及输出端检查，明确不改正常结束算法。若不能以薄点覆盖队列，保留限制并报告，不重写事件总线。 |
| 目前COPY-LINEAGE尚无完整来源版本 | 此时不能签发可信许可，不能用会话KB集合或模型声称的source_ids代替。先做依赖项。 |
| 每日过期扫描最多24h才提交stale | 生成撤销SLA从生命周期事实提交时刻T0计，不把它说成effective_until瞬间失效；若要求按时钟即时过期，另行确认策略读取规则。 |
| 已发送token、已复制客户端内容、供应商已收到的Prompt不能撤回 | 只承诺停止后续受控输出/调用；外部记录删除与已发生工具副作用不在此机制内。 |

SLA由用户确定并实测，不擅自承诺“立即”。可测上界为复核间隔 + 最多500ms请求 + context取消传播 + 可控输出队列处理；网络/TCP中已交付的数据不属于可撤回队列。无有效许可的持续输出不得无限等待下一轮查询。
